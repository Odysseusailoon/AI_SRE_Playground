## 🐛 Bug根本原因

### 代码路径:
```
1. Agent完成检测 → submit("Yes")
2. Orchestrator触发 fault recovery
3. inject_virtual.py:64 调用 get_service_json()
4. kubectl.py:73 尝试 json.loads(空字符串)
5. 抛出 JSONDecodeError
```

### 问题代码:
```python
# File: aiopslab/service/kubectl.py:73
def get_service_json(self, service, namespace, deserialize=True):
    result = self.run_kubectl(f"get service {service} -n {namespace} -o json")
    return json.loads(result) if deserialize else result  # ❌ result可能是空字符串
```

### 为什么kind1没有触发这个bug？

查看kind1的日志第46-49行:
```
== Fault Recovery ==
Recovering for service: user-service | namespace: test-social-network
Service: user-service | Namespace: test-social-network
```

**kind1也执行了fault recovery，但没有报错！**

再看kind的日志第51行之后立即就是错误堆栈，说明：
- kind1的recovery过程可能在service已经不存在的情况下，提前返回了
- 或者kind1的service删除时机不同
