# 并行执行功能实现说明

## 📋 修改概述

为 `service_api.py` 添加了 **Kind 集群池管理**，实现真正的并行任务执行。

---

## 🎯 核心原理

### 问题
原代码虽然有 `asyncio` 并发框架，但所有任务都使用**同一个 Kind 集群**，导致：
- Helm release 名称冲突
- Kubernetes 资源竞争
- 任务串行化执行

### 解决方案
引入 **集群池（Cluster Pool）**：
```python
集群池 = [kind, kind1, kind2, kind3]

任务执行流程：
1. 从池中获取一个空闲集群（阻塞等待）
2. 设置环境变量：AIOPSLAB_CLUSTER=kind1
3. 执行任务（自动使用指定集群）
4. 归还集群到池中
```

### 3. 修改 `_run_single_episode` 函数（第617-752行）

**修改前**：
```python
async def _run_single_episode(...) -> JobRunResult:
    async with semaphore:
        reward_config = _build_reward_config(problem.reward_config)
        handle = await asyncio.to_thread(
            service.reset_rl_environment, ...
        )
        # ... 执行任务 ...
```

**修改后**：
```python
async def _run_single_episode(...) -> JobRunResult:
    # 1. 从集群池获取一个可用集群
    cluster_name = await _acquire_cluster()
    try:
        # 2. 设置环境变量
        os.environ['AIOPSLAB_CLUSTER'] = cluster_name
        logger.info(f"Task {problem.problem_id}[{run_index}] using cluster: {cluster_name}")
        
        async with semaphore:
            reward_config = _build_reward_config(problem.reward_config)
            handle = await asyncio.to_thread(
                service.reset_rl_environment, ...
            )
            # ... 执行任务 ...
    finally:
        # 3. 归还集群到池中
        await _release_cluster(cluster_name)
        # 4. 清理环境变量
        if 'AIOPSLAB_CLUSTER' in os.environ:
            del os.environ['AIOPSLAB_CLUSTER']
```

## ⚙️ 配置说明

### 修改可用集群列表
编辑 `service_api.py` 第395行：
```python
_AVAILABLE_CLUSTERS = ["kind", "kind1", "kind2", "kind3"]  # 根据实际情况修改
```

### 并发数限制
- **最大并发数 = 集群数**
- 如果 `concurrency > 集群数`，多余的任务会排队等待
- 例如：4个集群，`concurrency=6` → 前4个任务立即执行，后2个排队

## ✅ 优势

1. **无需修改底层代码**
   - `aiopslab/config.py` 已支持 `AIOPSLAB_CLUSTER` 环境变量
   - 无需改动 AIOpsLab 核心逻辑

2. **自动排队机制**
   - 使用 `asyncio.Queue` 实现
   - 集群用完时自动阻塞等待
   - 无需手动管理锁

3. **资源隔离**
   - 每个任务独占一个 Kind 集群
   - 避免 Helm release 冲突
   - 避免 Kubernetes 资源竞争

4. **可扩展性**
   - 轻松添加更多集群
   - 支持动态调整并发数

## 📝 注意事项

1. **环境变量作用域**
   - 环境变量在 **主进程** 中设置
   - `asyncio.to_thread` 会继承主进程的环境变量
   - 任务结束后自动清理环境变量

2. **集群初始化**
   - 集群池采用 **延迟初始化**（Lazy Initialization）
   - 第一次调用 `_acquire_cluster()` 时才创建队列
   - 避免在模块导入时执行异步操作

3. **异常处理**
   - 无论任务成功还是失败，都会归还集群
   - 使用 `finally` 块确保资源释放
   - 即使发生异常，集群也不会丢失

4. **并发 vs 并行**
   - `concurrency` 参数控制 **同时执行的任务数**
   - 每个任务的 `runs` 仍然是 **串行执行**
   - 例如：`concurrency=2, runs=3` → 2个任务并行，每个任务3轮串行
